1. Python requests module
The requests module is a Python library used to communicate with websites and web services over HTTP. It gives Python programs an easy way to send requests such as GET, POST, PUT, PATCH and DELETE. For example, a GET request can ask an API for data and a POST request can send new data. The response object contains useful information such as the status code, headers and response body. JSON responses can normally be converted into Python data with response.json().

2. JSON and XML
JSON (JavaScript Object Notation) is a text format that stores information using objects, arrays, names and values. It is common in web APIs because it maps neatly to structures such as Python dictionaries and lists.

JSON advantages:
- It is fairly short and easy for people to read.
- It normally uses less data than XML because it has fewer tags.
- It maps naturally to objects, lists, strings, numbers and booleans.
- It is widely supported by modern programming languages and REST APIs.

JSON disadvantages:
- It does not support comments in the standard format.
- Very large or deeply nested JSON can become difficult to read.
- It has less built-in document/metadata features than XML.
- Incorrect commas, quotes or brackets can make the whole document invalid.

XML (Extensible Markup Language) stores information inside custom opening and closing tags. It is useful when data is document-like, needs attributes, or has to follow a strict schema.

XML advantages:
- Tags make the meaning and structure of data explicit.
- Attributes and namespaces are useful for complex documents.
- XML can be validated with technologies such as XSD.
- It is established in many older business and enterprise systems.

XML disadvantages:
- Opening and closing tags make files longer than equivalent JSON.
- It is usually more verbose and slower for a person to write.
- Parsing can be more complicated than simple JSON data.
- Namespaces and deeply nested tags can make XML difficult to understand.

3. RESTful APIs
A RESTful API is a way for programs to communicate over HTTP while treating information as resources. A resource is normally identified by a URL. HTTP methods describe the action: GET reads data, POST creates data, PUT/PATCH updates data and DELETE removes data. Servers commonly return JSON together with HTTP status codes. REST is stateless, meaning each request should contain the information needed to process it instead of depending on a conversation stored in the server.

REST advantages:
- It uses normal HTTP methods that web developers already understand.
- The client and server can be developed separately.
- Stateless requests can make scaling easier.
- REST can work with different data formats, although JSON is very common.

REST disadvantages:
- A client may need several requests to collect related resources.
- There is no single strict REST specification that forces every API to look the same.
- Poorly designed endpoints can become confusing or inconsistent.
- Statelessness means authentication/context information may need to be sent repeatedly.
